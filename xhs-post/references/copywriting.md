# 小红书文案规范(技术/学术类)

面向的是"把专业产出讲给半懂或不懂的人听"。与公众号长文不同:小红书是**信息流里抢三秒**,
但读者一旦点开,又比想象中愿意读长内容——所以钩子要狠,正文可以实。

## 结构

```
标题        一句话 + 一个 emoji。给结论或给反差,不给主题词
正文段 1    钩子。把最反直觉/最具体的那个发现直接说出来,不铺垫
正文段 2-4  分点展开。每点一个小标题 + 2-3 句
踩坑段      "我踩了什么坑"。这一段的可信度高于全文其它部分
限定段      结论的边界条件。写了它,前面的话才立得住
话题标签    5-8 个,从宽到窄:领域词 → 场景词 → 工具词
```

**标题**:给结论("先撞的不是电力墙,是数据墙")或给反差("我把做 PPT 写成了会报错的规则"),
不要给主题词("关于 AI 算力的一些思考")。主题词式标题在信息流里等于没有标题。

**首段**:直接给最具体的那个发现。不要"最近在研究 X""相信大家都遇到过"——
这两句是小红书上最典型的划走触发点。

## 三条硬规则

1. **每个数字都要有出处。** 页数、耗时、指标、对比值,只写能在实际文件或终端输出里
   找到的。记不准就不写。编造的数字读者未必当场识破,但作者要为它负责。

2. **必须有"踩坑"。** 技术类笔记里最可信的部分永远是"我做错了什么"。
   它同时解决两件事:证明你真做过;给读者可迁移的东西。没有踩坑的笔记读起来像广告。

3. **限定条件不能省。** "在纯文本路线不变的前提下""这套数据是合成示意值"——
   省掉这类限定能让文案更响,但那是拿准确性换传播,不做。

## 词表:出现即改

这些词在小红书的技术类笔记里密度极高,是"AI 写的/营销号写的"的直接信号。

| 类别 | 出现即改 |
|---|---|
| 空词 | 赋能、抓手、闭环、颗粒度、护城河、底层逻辑、生态位 |
| 营销腔 | 干货满满、建议收藏、划重点、家人们、姐妹们、绝了、yyds |
| 万能开头 | 最近在研究、相信大家都遇到过、随着……的发展、在当今……的时代 |
| 空洞收尾 | 希望对你有帮助、欢迎交流、点赞收藏不迷路、总而言之 |
| 虚假强调 | 强烈推荐、必看、震惊、颠覆、革命性、史上最全 |
| 数字夸张 | 效率提升 10 倍、一分钟搞定、零基础也能(除非确有其事且能给出处) |

**排比与三连要克制。** "更快、更稳、更强"这类节奏在小红书上读起来像广告词。
句长有变化、允许短句,比整齐更可信。

**emoji 用作分隔而不是装饰。** 每个小标题前一个足够;段内插 emoji 会打断阅读。

## 长度

用户没指定时按 **1000 字以内**。正文 600-850 字是舒服区间:
短于 500 字撑不住前面十几张图,长于 1000 字在手机上需要多次"展开"。

字数只算正文,不含标题与话题标签。

## 话题标签

5-8 个,从宽到窄排列,让不同层级的流量都能进来:

```
#人工智能 #AI          ← 领域词,量大但竞争激烈
#论文 #科研工具         ← 场景词,精准
#ClaudeCode #Scaling   ← 工具/专有词,量小但转化高
```

不要堆到十几个——标签过多会被判定为营销内容。

## 自查清单

- [ ] 标题给的是结论或反差,不是主题词
- [ ] 第一段没有"最近在研究""相信大家"
- [ ] 每个数字都能找到出处
- [ ] 至少一处踩坑
- [ ] 限定条件写了
- [ ] 词表零命中
- [ ] 结尾不求赞不求关注
- [ ] 正文字数在区间内
