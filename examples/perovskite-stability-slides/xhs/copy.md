# 小红书文案（正文 738 字）

## 标题

我把「做学术 PPT」写成了一套会报错的规则 📐

## 正文

组会和答辩做 PPT，最耗时的从来不是内容，是排版。图放多大、标题几行会溢出、这一页是不是太空——每次都得重新拍一遍坐标。

于是我把这件事写成了代码。不手拍坐标，只声明"这页放哪些块"，位置、间距、字阶、页码全交给布局引擎算。

真正有用的是那些**会报错的规则**👇

📌 全篇一张真实照片都没有 → 警告。学术汇报配真图才专业，这条不能靠自觉，得让它成为一个决定而不是一次遗漏

📌 页面填充率低于 62% → 提示这页太空，并给出四种补法。刻意不自动放大字号，那只会把一个问题换成另一个

📌 饼图超过 3 类 → 报错，建议换成水平条形图。人眼判别扇形角度本来就不可靠

📌 内置 108 条 AI 词表 →「赋能」「闭环」「具有重要意义」当场拦下

📌 结束页没写结论 → 警告。Q&A 全程停在那一页，只挂一句"恳请批评指正"太浪费了

踩过的坑也记一下 🕳️

· 封面渐变一开始用色块阶梯拼，150dpi 下量出来相邻级差 ΔRGB 到 (5,12,12)，肉眼直接读成条纹——那正是我想躲的"AI 味色块"。最后往 XML 里注入真渐变才干净

· 饼图颜色不够用时，pptxgenjs 会 Math.random() 取色，同一个脚本跑两次颜色不一样

· 图表里的中文会变成等线体，因为库压根不写 `<a:ea>` 标签，得自己补进去

我还拆了两份真实的学生汇报做参考。结论有点意外：它们的内容页排版其实不如我这套（手拍坐标，已经拍出重叠和切字），但**首尾页确实更强**——封面留"面"，结束页只留一道细线，两者落在同一条水平线上，一厚一薄。这个呼应关系我照着做了。

现在改完脚本重跑，几秒出稿，19 页答辩 PPT 警告清零。

工具是 Claude Code + 自己写的 skill，全程本地跑。
