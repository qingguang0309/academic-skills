# 笔记格式规范

标准样本：vault 里的 `01-Claude笔记摘录/哈希函数的原理与用途.md`。能读到它时先读一遍，以它的实际写法为准；本文件是从它和同目录其他笔记归纳出的规则。

## 骨架

```markdown
---
tags: [claude总结, 学习笔记]
created: 2026-09-20
source: claude-chat
---
```

## 逐项规则

### frontmatter

- 只用 `tags`、`created`、`source` 三个字段（更新时可加 `updated`）。
- `tags`：行内数组 `[a, b]` 或多行列表都可以，与目录里多数笔记保持一致即可。第一个固定为 `claude总结`；第二个按领域选已有标签（`学习笔记`、`AI工程` 等），确实没有合适的才新建，新建也用短中文词。
- `created`：写笔记当天的日期，`YYYY-MM-DD`。
- `source`：`claude-chat`（claude.ai / 桌面版对话）、`claude-code`（Claude Code）、`claude-cowork`（Cowork）。更新时内容来自另一个渠道，就追加在后面：`source: claude-code, claude-chat`。

### 文件名

- 就是笔记标题，概括主题而不是复述问题："哈希函数的原理与用途"，不是"哈希是什么意思"。
- 常见形态：`主题：副题`（全角冒号）、`A、B 与 C`、`X 的机制与用途`。中英混排时英文两侧留空格（`tmux：机制与常用操作`、`HTTP 返回码清单与 API 中转站实测`）。
- 禁用字符：`/ \ : * ? " < > | # ^ [ ]`。

### 开头

- 不写 `# 一级标题`。
- **核心概念卡（可选）**：全文围绕一个具体对象（某个算法、工具、协议）时，第一节写 `## 对象名`，下一行紧跟 `简介：` + 两三句大白话定义。没有这样的单一对象就省略。
- **导语（必有）**：一段，两三句。第一句说清对象是什么或解决什么问题，第二句说这篇覆盖哪几块。可以用 `==高亮==` 标出全文最关键的一句结论，一篇最多两三处。不写"本文将介绍""下面我们来看看"。

### 主体小节

- `##` 二级标题为主，标题是内容本身（"机制：进程挂在谁下面""裸 IP 访问会落到哪个站"），不用"概述""详细介绍""总结"这类空标题。需要更细层级再用 `###`。
- 先给结论，再讲为什么。机制要讲到因果链（"因为输出长度固定，大量信息被丢掉，所以不可逆"），不只罗列特性。
- 并列的几项用法/场景：每段以**加粗短句**开头，句号结尾，后接解释，段尾括号注明依赖的原理，如"（单向性）"。
- 有先后或要编号引用的性质：用有序列表，`**名称**：解释`。
- 命令、代码、文件名、配置项用行内代码或代码块；代码块注明语言。数字、版本号、实测结果照对话原样写，注明条件。
- 用户自己的环境和实测（"服务器 2 路 180 核""中转站返回 502"）是这类笔记最有价值的部分，保留，并说清是在什么条件下得到的。
- 对话后半段修正了前面说法的，正文只写修正后的版本；修正点本身有教育意义时，单独写一句"常见说法是……，准确地说是……"。
- 和已有笔记有出入时，在相应位置点明："[[某篇笔记]] 里说的 X 要精确化：……"。
- 未展开、待核实的方向可以在主体最后一句带过（"未展开的方向：……"），不要硬写。

### 相关

- 有实质联系的已有笔记才链，用 `[[文件名不带 .md]]`。
- 每条后接 `——` 和一句话说明具体联系（"本篇挡住请求的那台网关就是那篇讲的正向代理"），而不是"相关笔记"。
- 双链目标必须是真实存在的文件名，逐字核对（包括全角/半角冒号和空格）。

### 术语表

- 必有，放在全文最后。
- 格式固定：`- **术语** — 解释`（加粗术语，空格 + 破折号 `—` + 空格）。需要补全称时写在破折号前：`- **DHCP**：全称 Dynamic Host Configuration Protocol（动态主机配置协议） — 解释`。中英并列写成 `**会话（session）与窗格（pane）**`。
- 收正文里出现的、外行读者可能卡住的词，一般 5–12 条。
- 解释写给没背景的人：一两句大白话，必要时补一句"它在这里起什么作用"。不要用另一个术语解释术语。

## 文风

- 中文书面语，短句，直接陈述。可以口语化的比喻（"指纹""秒传"），但不要聊天腔。
- 不出现对话痕迹：不写"你问""我""Claude 说""刚才""如上所述""希望对你有帮助""好问题""总的来说"。
- 不堆三段式排比、不写"值得注意的是""至关重要""深入探讨"这类 AI 套话。
- 能用一个例子说清的不用三句抽象描述。
- 笔记长度跟着内容走：一个小知识点 10–30 行，一次完整排障或系统讲解可以到 100–200 行。不为凑格式注水。
