# 对话 → Obsidian 笔记

把一段对话里真正学到的东西，写成一篇**半年后自己单独打开也能看懂**的知识笔记，落到 Obsidian vault 里。笔记是知识，不是会议纪要：读者看不到原对话，也不关心谁问了什么。

格式标准以 vault 里的 `哈希函数的原理与用途.md` 为准，完整模板和逐项规范见 [references/note-format.md](references/note-format.md)——**动笔前先读它**。

## 写文件用什么工具

- **Claude 桌面版 / claude.ai 对话**：用 Filesystem 扩展（MCP）的工具：`list_allowed_directories`、`list_directory`、`search_files`、`read_text_file`（旧版叫 `read_file`）、`write_file`、`edit_file`。先调 `list_allowed_directories` 确认 vault 在授权范围内；不在就停下，告诉用户到 Filesystem 扩展设置里把 vault 目录加进允许列表，不要换地方写。
- **Claude Code**：用原生 Read / Write / Edit / Glob。可以额外跑 `scripts/check_note.py` 做机检（见第 6 步）。
- 不要把笔记内容只贴在回复里了事，也不要写到下载目录或临时目录——目标就是 vault 里的那个文件。

## 默认路径

| 项 | 默认值 |
|---|---|
| vault 根目录 | `/Users/qingguang/Documents/Obsidian/` |
| 笔记目录 | `/Users/qingguang/Documents/Obsidian/01-Claude笔记摘录/` |

用户指定了别的目录就用用户的。双链可以指向 vault 根目录下任何位置的笔记（例如根目录的 `OpenVPN&网络基础知识.md`），不限于笔记目录。

## 流程

### 1. 摸清现有笔记

`list_directory` 列出笔记目录，必要时 `search_files` 在 vault 根目录按关键词搜。目的有三个：

- **查重**：本次主题是否已有笔记。有 → 走"更新"路线（第 4 步），不新建。
- **找双链对象**：和本次内容有实质联系的笔记，读一下它们的导语和小节标题，确认联系点具体是什么。
- **沿用标签**：读几篇现有笔记的 frontmatter，复用已有标签（如 `claude总结`、`学习笔记`、`AI工程`），不发明近义新标签。

### 2. 从对话里提炼

逐段过一遍对话，只留下能独立成立的知识：

- **留**：结论、机制（为什么）、判据（怎么区分/怎么判断）、具体例子和数字、命令与代码、踩过的坑和最终做法、用户自己环境的关键事实（"2 路 180 核""服务器在阿里云"这类会影响结论的背景）。
- **删**：寒暄、来回追问的过程、走错又放弃的路线（除非"为什么这条路不行"本身是知识）、Claude 的客套和自我更正痕迹。
- **合并更正**：对话后半段推翻或精确化了前面的说法时，笔记里只写最终正确的版本；如果旧说法是常见误解，可以点明"常见说法是 X，准确地说是 Y"。
- **一次对话多个主题**：主题之间没有从属关系就拆成多篇，每篇单独成文，彼此用双链连起来；先向用户列出拆分方案再写。
- 对话里没讲清、Claude 也不确定的地方，不要在笔记里编造补全；要么不写，要么明确标注"未展开"或"待核实"。

### 3. 按格式成稿

严格按 [references/note-format.md](references/note-format.md)。要点速记：

- 文件名 = 主题标题，中文为主，副题用全角冒号：`tmux：机制与常用操作.md`。不含 `/ \ : * ? " < > | # ^ [ ]`（半角冒号不行，全角"："可以）。
- frontmatter 三个字段：`tags`（首个必为 `claude总结`）、`created`（今天，YYYY-MM-DD）、`source`（`claude-chat` / `claude-code` / `claude-cowork`，按对话发生的位置）。
- 正文**不写一级标题**（Obsidian 用文件名当标题）。开头一段导语交代"这篇讲什么、为什么值得讲"；有一个贯穿全文的核心概念时，可在导语前放"核心概念卡"（`## 概念名` + `简介：……`）。
- 主体用 `##` 小节，标题写内容而不是写"概述""总结"。先结论后展开，机制讲到"为什么"。
- 末尾依次是 `## 相关`（有可链的笔记时）和 `## 术语表`（必有）。

### 4. 新建还是更新

- **新建**：`write_file` 写入新文件。写前确认同名文件不存在——`write_file` 会直接覆盖。
- **更新已有笔记**：先 `read_text_file` 读全文，再用 `edit_file` 做定点修改：新知识插进对应小节或新增小节，被新对话推翻的旧说法直接改正，术语表补新词。**不改 `created`**，可在 frontmatter 加一行 `updated: YYYY-MM-DD`。不要整篇重写覆盖，用户可能手动改过这篇。
- **回链**：新笔记链到了某篇旧笔记，且联系是双向成立的，就在旧笔记的 `## 相关` 里追加一行指回来（没有这一节就在 `## 术语表` 之前新建）。只追加，不动旧笔记的其他内容。

### 5. 写完回读

用读文件工具把刚写的文件读回来，逐项核对：

- [ ] frontmatter 能被解析（首行 `---`，三个字段齐全，日期格式对）
- [ ] 没有一级标题；导语存在且不是"本文将介绍……"式空话
- [ ] 每个 `[[双链]]` 都对得上第 1 步列出的真实文件名（不带 `.md`）
- [ ] 术语表存在，每条是 `- **术语** — 解释` 的格式，解释是大白话
- [ ] 全文没有对话痕迹（"你问""我刚才说""如上所述""希望对你有帮助""好问题"）
- [ ] 代码、命令、数字和对话里的一致，没有改写走样

### 6.（Claude Code 可选）机检

```bash
python3 scripts/check_note.py "/Users/qingguang/Documents/Obsidian/01-Claude笔记摘录/<笔记>.md"
```

脚本只用标准库，检查 frontmatter、一级标题、术语表格式、双链能否解析、对话痕迹词。有 error 就改到通过。桌面版对话里没有 shell，按第 5 步清单人工核对即可。

### 7. 回复用户

简短说明：写了哪几篇（给出完整路径）、是新建还是更新、加了哪些双链和回链、有哪些内容因为对话里没讲清而没写进去。不要在回复里重复整篇笔记内容。
