# 图表选型与原生图表实现

`chart` 块用 pptxgenjs 原生图表:PowerPoint 里可点开改数、与页面同色、不是死图。
但它只覆盖**简单量值图**;分布、误差棒、拟合线一律走 paper-figures 出矢量图再进 `figure` 块——
pptxgenjs 的图型只有 area/bar/bubble/doughnut/line/pie/radar/scatter,**没有箱线图、直方图,
也没有误差棒 API**。用柱状图假装直方图是拿版式凑证据。

## 一、数据形状 → 图型

| 数据形状 | 用什么 | 关键参数 | 为什么不用另一种 |
|---|---|---|---|
| 份额构成,≤3 类,只讲"某项过半" | 环形 `doughnut` | `holeSize 55–70`,中心放那个唯一数字 | 角度判别只在类别极少、差距悬殊时可靠 |
| 份额构成,≥4 类,或要读出具体份额 | 降序水平条 `barh` 单序列 | `showValue`,端点标数值,去图例 | 长度判别精度远高于角度;17% 与 19% 在饼图上分不出来 |
| 多个整体各自的内部构成 | 100% 堆叠条 `barh` + `stacked,percent` | 最重要成分贴基线,`其他`放最上 | 并排饼图是最难比较的形式,任何情况都不用 |
| ≤6 类 × 2–4 分组的量值对比 | 簇状柱 `bar` | `gapPct 50–80`,`overlapPct -10~0` | 同基线等宽柱是量值比较的黄金标准;一簇超 4 根注意力就被图例吃掉 |
| 类别名长(中文条件、样品全称)或 >6 类 | 水平条 `barh` | 要最大值在顶部就**自行反转** labels/values | 柱形图横轴放不下长中文,PowerPoint 会旋转 45°,是学术 PPT 头号失分点 |
| 排名/榜单,关心次序与断层 | 降序水平条 | 只给首尾加标签,其余同一浅灰 | 全部标数就成了伪装成图的表格 |
| 等间距时间序列,1–4 条 | 折线 `line` | 点数 ≤12 带圆点,更多用 `none`;**永不平滑** | 斜率直接编码变化率;样条插值会造出不存在的极值 = 用平滑伪造数据 |
| 论点是"累计量堆起来",≤3 序列 | 面积 / 堆叠面积 | `stacked` | >3 序列后除最底层都读不出数 |
| 离散、不等间距的少量时点(3 个批次) | 柱形 `bar`,**不是折线** | — | 连线宣称两点间存在连续过程;批次没有这种连续性,连线是未验证的插值断言 |
| 两个连续变量的关系 | 散点 `scatter`;要拟合线/置信带就改 matplotlib | — | 散点是唯一保留每个观测、能暴露非线性与离群点的图形 |
| 单变量分布:直方、箱线、小提琴、带误差棒的均值 | **matplotlib + figure 块** | — | 库无这些 API;而这些恰是结论的证据核心,不能降级 |
| 配对前后,n ≤ 30 | 斜率图/哑铃图(matplotlib) | — | 两根均值柱把"每个个体变了多少、方向是否一致"压成两个数字 |
| 单一关键数字(+34%、312 Wh·kg⁻¹) | 不画图:用 `stats` 块 | 顶部标尺线 + 一行口径 | 一根柱子用整块绘图区编码一个不需要比较的量 |
| 多指标画像,2–3 对象 × 5–8 指标 | 雷达 `radar` | 对象 ≤3,各轴先归一化 | 只在"轮廓形状本身就是结论"时用;面积随轴序改变,>3 对象完全糊掉 |

## 二、饼图判据(默认不用)

三条**全部成立**才允许:

1. 类别数 ≤ 3(含合并出的"其他")。硬上限,不是建议值——slidekit 超限会警告。
2. 论点只是"某项占多数"的粗粒度定性结论,听众不需要读出或比较具体份额。
3. 最大项与次大项相差 ≥ 15 个百分点,且各份额之和确实构成一个有意义的整体。

允许时的唯一正确形态:环形图 `holeSize 55–70`,中心放那个唯一要讲的数字,`showPercent` 开、
`showValue` 关(两者共用同一个数字格式,同开会把原始值也按百分比格式化)。

**任一命中即换图型**:≥4 类 → 降序水平条;要精确比较相近份额 → 水平条 + 端点标签;
比较多个整体的构成 → 100% 堆叠条(并排饼图始终禁止);份额随时间变化 → 堆叠面积或多折线;
各部分之和不构成整体(多选、指标不互斥)→ 饼图语义就是错的;存在 <5% 的小尾巴 → 合并成"其他"后重判第 1 条。

## 三、pptxgenjs 实现要点(slidekit 已内建,自己写图时照做)

**不显式传就等于没传**——库内是恒等赋值,`showValue`/`showPercent`/`showLegend`/`showTitle`
不给 `true` 就保持 undefined;标题类要"值 + 开关"成对(`valAxisTitle` 配 `showValAxisTitle:true`)。

**会让 PowerPoint 弹"需要修复"**:

- 堆叠柱传 `dataLabelPosition:'outEnd'` —— OOXML 规定堆叠只允许 `ctr`/`inBase`/`inEnd`。
- `shadow:{type:'none'}` —— 会拼出非法的 `<a:noneShdw>`;图表默认本就无阴影,不要传。
- 组合图任一子图设了 `secondaryValAxis`,必须在顶层同时给 `valAxes` 与 `catAxes` 两个数组、各 2 项。

**静默失效 / 不可复现**:

- 簇状柱的 `dataLabelPosition:'outEnd'` 会被库静默删掉,别指望该参数。
- 饼/环每片颜色按索引取 `chartColors`,**索引溢出就 `Math.random()` 取色**——同一脚本连跑两次得到两组颜色。slidekit 在色板不足时直接抛错,因为类别过多正是该换图型的信号。
- 饼/环上 `showValue` 与 `showPercent` 共用 numFmt,同开会把 46 显示成 `4600%`。
- 环形图的 `dataLabelPosition` 会被库无条件删除,标签位置不可控——这也是"类别要少"的工程理由。

**默认样式必须整套覆盖**:值轴默认带 1 pt 纯 `#888888` 粗网格线,这是"默认图很丑"的头号原因;
默认配色是 Office 2007 砖红/钢蓝。学术风固定组合:淡色细网格线 + 无值轴线 + 无刻度线 + 主题色板 +
`gapPct 50–80`。

**中文字体必须打补丁**:pptxgenjs 只写 `<a:latin>`,图表 XML 里从不出现 `<a:ea>`,中文轴标签会被
PowerPoint 回退到"等线",与正文字体不一致。slidekit 在 `build()` 后处理里解包 `ppt/charts/chart*.xml`
补 `<a:ea>`,与放映切换的注入合并成一次解包/打包。

## 四、图表也要过内容纪律

- 一页一个 exhibit:图表与公式不要同页(见 SKILL.md 第 3 步 QA)。
- 关键发现要能在图上看出来:排名图只标首尾、对比图给出差值注释——不要指望听众自己算。
- 数据来源与"是否实测"必须落到 caption:示意数据一律写明"合成示意数据,非实测"。
- 图表不是填空白的工具。如果一页只是因为太空才加图,回去看 content-discipline.md 的补救清单——先补论证,再补图形。
