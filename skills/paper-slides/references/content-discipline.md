# 内容纪律：让幻灯像人写的学术材料

版式再好，内容一读就是机器生成，整份材料照样掉档。本文管**文字与结构**。

论文的 AI 味主要在词汇（见 paper-polish 的 `references/deai-style-guide.md`，同仓库，词表可直接借用）；
**幻灯的 AI 味主要在结构**——因为幻灯本来就短，词汇病灶不多，暴露破绽的是"每页都长得一样"。
下面按幻灯特有的病灶组织，最后给一套"先审计后改写"的流程（方法借鉴
[academic-humanizer](https://github.com/AIScientists-Dev/academic-humanizer) 的分层审计与 claim–evidence 纪律）。

## 一、结构性 AI 味（幻灯头号病灶）

| 病灶 | 症状 | 处理 |
|---|---|---|
| **三项对称癖** | 每个 bullets 恰好 3 条、cards 恰好 3 或 6 个、创新点与局限数量相等 | 有几条写几条。2 条、4 条、5 条都正常；为凑对称硬造的那一条删掉 |
| **导语对仗强迫症** | `负担之重：/证据之偏：/方法之限：`——三个导语字数相同、结构相同 | 导语只做**功能标签**（`数据源：`/`验证：`），不做修辞对仗。修辞性对仗一律拆掉 |
| **每页同构** | 每张图页都配一个 callout、每个章节都是"概述+细节+小结"三页 | 页面结构由内容决定：有的图不需要解读框，有的章节两页讲完 |
| **标题排比** | 连续几页标题都是"A，B"的平衡双分句 | 长短交错：一句话标题、带数字的标题、带转折的标题混用 |
| **填满癖** | 每页内容都恰好铺满版面 | 留白是允许的。一页只有一个论点和一句话时，就让它只有那么多 |

自查动作：把全篇标题抄成一列，把每页的块类型抄成一列。**如果这两列出现明显的重复节拍，就是 AI 味。**

## 二、claim–evidence 纪律（学术专业度的核心）

每一句经验性陈述都要能回答"凭什么"。审计时逐条标注证据状态：

- **有数据支撑** → 动词可以强：`结果显示`/`观测到`。同时把数字放进句子里（`占其中约六成`优于`是主要结局`）。
- **间接或文献支撑** → 动词必须软：`提示`/`与……一致`；并给出处。
- **无支撑** → 要么补证据指针（哪张图、哪个附录、哪篇文献），要么降级为设想（`预期`/`拟`），要么删。
- **动词强度匹配证据强度**：没做统计检验就不要写"显著"；没做因果设计就不要写"导致"。
- 给**范围**而非孤零零的均值：`40–80 μg m⁻³` 优于 `约 60 μg m⁻³`。
- 目标类材料（开题/基金）里所有数值都必须标明是目标而非结果——用 `callout tone:"warn"` 全篇声明一次。

## 三、词汇与句式（幻灯精简版）

幻灯字少，下面这几类最容易漏进来：

- **许愿式套话**：`为……提供新思路`/`开辟新途径`/`具有重要意义`/`为……提供量化依据`。改成具体后果：`可支撑标准修订时的收益测算`，或直接删。
- **空洞强调**：`充分/深入/系统性/全面地`。删掉后句子没丢信息，就是水词。
- **"不止…而是…"/"既…又…"**：对仗句式在幻灯里格外扎眼，拆成陈述句。
- **循环表述**：`高精度暴露评估提升了暴露评估精度`。用结论解释结论 = 没说。
- **方法当结论**：`我们进行了 Cox 回归分析`不是结论；结论要给出回归看到了什么。
- **动名词标题**：`基于……的研究`/`关于……的探讨`——学位论文标题可以，幻灯页标题必须给结论。

不要过度清洗：`提示`/`可能`/被动语态/`本研究`都是**合法的学术构造**，不是 AI 味。该 hedge 的地方硬改成断言，是把一种病换成另一种。

## 四、演讲者备注也算内容

`notes` 是给自己上台用的，不是给评审看的。合格的备注写"这页要说什么、被问什么怎么答"，
不是把页面文字换个说法重复一遍。备注里出现`本页展示了……`就是复述，删掉重写。

## 五、工作流：先审计，后改写

照抄下面顺序，**不要边写边改**——边写边改会漏掉结构性病灶（它们只有把全篇摊开才看得见）。

1. **摊开**：把全篇 action title 抄成一列，每页块类型抄成一列，每页 bullets 条数抄成一列。
2. **审计**（不动手改）：对照第一节找结构重复节拍；对照第二节给每条经验陈述标注证据状态（有数据／文献／无支撑）；对照第三节圈出套话与空洞强调。
3. **改写**：只改被点出来的地方。保留数据、引文、页型结构；不要顺手重写没问题的句子。
4. **复检**：再抄一次三列。节拍是否已经打散？无支撑陈述是否都补了指针或降级了？

改完在交付说明里列一张表，让用户看到改了什么、为什么改：

```markdown
| 原表达 | 改为 | 病灶 |
|---|---|---|
| 负担之重：/证据之偏：/方法之限： | 三条改为功能性陈述，第三条换开头 | 导语对仗强迫症 |
| 为标准修订提供量化依据 | 可支撑标准修订时的收益测算 | 许愿式套话 |
| 心血管疾病是主要结局 | 心血管疾病占归因死亡约六成 | 有数据不给数据 |
```
