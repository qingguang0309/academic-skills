# 内容纪律：让幻灯像人写的学术材料

版式再好，内容一读就是机器生成，整份材料照样掉档。本文管**文字与结构**。

一句话原则：**少做包装，把具体问题、实际工作和证据讲清楚。**

随手可用的检验：**这句话换到别人的课题里是否照样成立？** 成立，多半还太空泛——补上研究对象、方法、条件或证据，通常就自然了。"构建智能分析框架"放进任何课题都成立；"用化学位移和线宽约束谱峰拟合"只属于这个课题。

论文的 AI 味主要在词汇（见 paper-polish 的 `references/deai-style-guide.md`，同仓库，词表可直接借用）；
**幻灯的 AI 味主要在结构**——幻灯本来就短，词汇病灶不多，暴露破绽的是"每页都长得一样"。
下面按幻灯特有的病灶组织，最后给一套"先审计后改写"的流程（方法借鉴
[academic-humanizer](https://github.com/AIScientists-Dev/academic-humanizer) 的分层审计与 claim–evidence 纪律）。

## 一、结构：围绕研究展开，不套模板

每个研究部分按**问题是什么 → 采用什么方法 → 结果如何 → 还有什么困难**展开。这条线决定页序与条目，版面不决定。困难要写具体（哪一步没做通、为什么、打算怎么试），不能只写"有待进一步研究"。

| 病灶 | 症状 | 处理 |
|---|---|---|
| **套分类模板** | 每页都是"基础/核心/延伸""方法/系统/生态""数据/模型/应用"三分；类名整齐，底下说的是同一件事 | 按研究线索排。真有并列的几件事才分类，类名用研究里的具体名词（`谱峰拟合`/`仪器联调`），不用抽象层级词。这类分类最常以卡片网格出现——全文不用卡片，slidekit 对任何卡片都报警 |
| **三项对称癖** | 每个 bullets 恰好 3 条、cards 恰好 3 或 6 个、创新点与局限数量相等 | 有几条写几条。2 条、4 条、5 条都正常；为凑对称硬造的那一条删掉。全篇四分之三以上的 bullets 都是 3 条时 slidekit 报警 |
| **导语对仗强迫症** | `负担之重：/证据之偏：/方法之限：`——三个导语字数相同、结构相同 | 导语只做**功能标签**（`数据源：`/`验证：`），不做修辞对仗 |
| **三处重复** | 标题、结论条、正文、底部横条或"小结"框把同一件事说好几遍 | 同一句话只出现一次：标题点明主题，结论写进结论条，正文放依据，底部横条只在需要额外强调时用。"小结/总结/启示"类提示框、与正文高度重复的提示框、与结论条重复的横条，slidekit 都报警 |
| **每页同构** | 每张图页都配一个 callout、每个章节都是"概述+细节+小结"三页 | 页面结构由内容决定：有的图不需要解读框，有的章节两页讲完 |
| **卡片网格** | 并列的几件事排成一行卡片 | 全文不用卡片、胶囊和圆角框：比较用三线表，过程用流程图，结果用数据图，并列要点用 bullets。用了卡片 slidekit 就报警 |
| **标题同构** | 连续几页标题都是"X 的构建""Y 的构建"，或都是"A 与 B" | 标题只点明这页讲什么，用研究里的具体名词 |
| **填满癖** | 每页内容都恰好铺满版面 | 留白是允许的。一页只有一个点，就让它只有那么多；放不下时**先删字，再考虑缩字号**（引擎自动降字号时会报警提醒） |

自查动作：把全篇标题抄成一列，每页块类型抄成一列。**这两列出现明显的重复节拍，就是 AI 味。**

## 二、标题与正文：标题点主题，论述留给口头

- **标题简短，直接点明主题**：`谱峰拟合方法`、`原型测试与后续验证`、`局限与下一步`。中文约 18 字以内，不带逗号句号；不写成结论句，也不写成口号（`让仪器像专家一样思考`）。标题超长或像句子时 slidekit 报警。
- **结论写进页题下的结论条**：每个内容页一句 `conclusion`，写具体事实和数字，关键数据用 `**…**` 标主色加粗——写`线宽约束把残差中位数从 **7.4%** 降到 **3.1%**`，不写`显著提升了拟合精度`。大纲阶段给每页多写一列"这页要讲清的结论"，这一列通读应当讲完整个论证，写脚本时直接落成结论条。缺结论条、结论条没数字、超过两行，slidekit 都报警；研究计划这类确实没有结论的页传 `conclusion: false`。
- **页底横条按需用**：`banner` 是主色底白字的横条，只在需要额外强调一句（如"下一步"）时用，不能复述结论条。
- **正文适合讲述**：页面只留关键依据（数字、条件、图上的标注），完整论述放进口头与演讲者备注。一条要点写成两三行的完整段落，就是把讲稿贴上了页面。
- **强调克制**：粗体只给导语，不整段加粗（`text` 块整段加粗时 slidekit 报警）。

## 三、结论有分寸：区分完成与计划

每一句经验性陈述都要能回答"凭什么"，还要让听众分清**哪些做完了、哪些是初步结果、哪些还没做**。

- **显式标状态**：bullets / stats / cards 的条目加 `status: "done" | "prelim" | "planned"`，页面上渲染为【已实现】【初步测试】【拟开展】。开题、中期、基金汇报里完成与计划常在同一页，不标就是在模糊处理。
- **数据交代条件**：数值要带测试条件、样本量和适用范围——`拟合残差中位数 3.1%（12 张 ¹H 谱，25 °C）`优于`拟合精度高`。stats 大数字不写 `note` 时 slidekit 报警。
- 给**范围**而非孤零零的均值：`40–80 μg m⁻³` 优于 `约 60 μg m⁻³`。
- **判断要有对应证据**：`全部达标`要逐项给数；`填补空白`要给检索范围；`可低成本推广`要有成本核算或推广试验，没有就标【拟开展】或删。词表把这几类列为 always 档。
- **动词强度匹配证据强度**：
  - 有数据支撑 → 动词可以强：`结果显示`/`观测到`，同时把数字放进句子里（`占其中约六成`优于`是主要结局`）。
  - 间接或文献支撑 → 动词必须软：`提示`/`与……一致`，并给出处。
  - 无支撑 → 补证据指针（哪张图、哪个附录、哪篇文献），或降级为【拟开展】，或删。
  - 没做统计检验就不要写"显著"；没做因果设计就不要写"导致"。
- 目标类材料（开题/基金）里的数值必须标明是目标而非结果——条目用 `status: "planned"`，或用 `callout tone:"warn"` 全篇声明一次。

## 四、真实细节比概念图有说服力

- 素材优先级：**实测谱图、原始数据图、系统截图、失败案例、具体限制** > 实景照片 > 概念架构图 / AI 示意图。一张带噪声的实测谱图，比一张干净的"平台架构图"更能说明你做了什么。
- 失败案例要讲：哪次拟合没收敛、哪台仪器的数据对不上、原因是什么。它比成功案例更能证明工作是真的。
- **图注分清实测与示意**：figure / chart 块加 `evidence: "measured" | "screenshot" | "photo" | "literature" | "simulated" | "schematic"`，图注自动带【实测】【截图】【实拍】【文献数据】【模拟】【示意】。没标的图 slidekit 报警；fetchimg / aiimg 取来的图已由署名行交代来源，不报。
- **图里的措辞一起改**：流程图节点、架构图标签里的"智能中枢""持续进化"同样是口号。`wordlint.py` 能直接扫流程图 JSON：`python3 wordlint.py deck.js assets/*.json`。

## 五、词汇与句式（幻灯精简版）

幻灯字少，下面这几类最容易漏进来：

- **口号**：`赋能`/`持续进化`/`最后一公里`/`构建通用框架`/`一站式`，以及拟人化的`让仪器像专家一样思考`。直接说做什么、怎么做：`用化学位移和线宽约束谱峰拟合`。
- **许愿式套话**：`为……提供新思路`/`开辟新途径`/`具有重要意义`。改成具体后果：`可支撑标准修订时的收益测算`，或直接删。
- **空洞强调**：`充分/深入/系统性/全面地`。删掉后句子没丢信息，就是水词。
- **"不止…而是…"/"既…又…"**：对仗句式在幻灯里格外扎眼，拆成陈述句。
- **循环表述**：`高精度暴露评估提升了暴露评估精度`。用结论解释结论 = 没说。
- **只交代做过什么**：`我们进行了 Cox 回归分析`只说了做过什么；正文还要写回归看到了什么。
- **长动名词标题**：`基于……的……研究`/`关于……的探讨`放在幻灯页标题上太长太虚，改成`谱峰拟合方法`这类短主题。
- **假上下标**：`29Si`、`R2`、`Q3`、`δ_cal`、`CO2` 在投影上一眼就是没排版。写 `^{29}Si`、`R^{2}`、`Q^{n}`、`δ_{cal}`、`CO_{2}`（slidekit 渲染为真上下标），或直接用 Unicode `²⁹Si`、`R²`；slidekit 对假上下标报警。

不要过度清洗：`提示`/`可能`/被动语态/`本研究`都是**合法的学术构造**，不是 AI 味。该 hedge 的地方硬改成断言，是把一种病换成另一种。

## 六、演讲者备注也算内容

`notes` 是给自己上台用的，不是给评审看的。标题只点主题、正文只留依据之后，**完整论述就写在备注里**：这页要说清的结论、怎么从证据讲到结论、被问什么怎么答。备注里出现`本页展示了……`就是复述，删掉重写。

## 七、词汇：四档判定 + 白名单

词表在 [ai-wordlist.json](ai-wordlist.json)，用 `scripts/wordlint.py` 扫描，不靠"记得避开"：

| 档位 | 判定 | 处理 |
|---|---|---|
| `hard` | 单次出现即报 | 必改。生成痕迹（`utm_source=chatgpt.com`）、未填占位符、无出处引用（`专家表示`/`相关研究显示`） |
| `always` | 单次即报，可豁免 | 口号、许愿式套话、无证据的全称判断与水平判断、空枢纽句、时代背景开场、助手路标 |
| `density` | 同页 ≥2（短）/≥3（长）才报 | 单个用是正常的，堆砌才是病：`多维度`/`全流程`/`进行+V`/连接词 |
| `struct` | 脚本查不了 | 三项对称、句长均质、标题同构——交第八节的人工节拍审计 |

**白名单优先于一切档位**：`鲁棒性`/`可持续性`/`可解释性`/`数字化`/`深度学习`/`选择性`/`活性` 等是正常术语，
永不报。判据是"删掉这个词句子有没有丢信息"——丢了就是术语，没丢才是水词。

论文语体用 `--lang paper` 放行幻灯专属规则（论文里"进行分析""具有重要意义"是规定动作）。

**词表会过时，别只维护词表。** GPT-4 时代的强痕迹词已大幅收敛，仍高频的只剩 showcase/highlight/enhance 一组；
结构性痕迹比词汇稳定得多。**词表命中清零 ≠ 通过审计**，节拍审计不能省。

## 八、工作流：先审计，后改写

照抄下面顺序，**不要边写边改**——边写边改会漏掉结构性病灶（它们只有把全篇摊开才看得见）。

1. **摊开**：把全篇页标题抄成一列、大纲里的结论列抄成一列，每页的块类型、bullets 条数、status 各抄成一列。
2. **审计**（不动手改）：对照第一节找结构重复节拍、看每部分是否走完"问题—方法—结果—困难"；对照第三节给每条经验陈述标注证据状态（有数据／文献／无支撑）和完成状态；对照第五节圈出口号与套话；每句过一遍"换到别人的课题里是否照样成立"。
3. **改写**：只改被点出来的地方。保留数据、引文、页型结构；不要顺手重写没问题的句子。
4. **复检**：再抄一次各列。节拍是否已经打散？无支撑陈述是否都补了指针或降级了？完成与计划是否都标清了？

改完在交付说明里列一张表，让用户看到改了什么、为什么改：

```markdown
| 原表达 | 改为 | 病灶 |
|---|---|---|
| 让仪器像专家一样思考 | 用化学位移和线宽约束谱峰拟合 | 拟人化口号 |
| 各项指标全部达标 | 6 项指标中 5 项达标，灵敏度未达标（n = 12） | 无证据的全称判断 |
| 负担之重：/证据之偏：/方法之限： | 三条改为功能性陈述，第三条换开头 | 导语对仗强迫症 |
| 为标准修订提供量化依据 | 可支撑标准修订时的收益测算 | 许愿式套话 |
| 心血管疾病是主要结局 | 心血管疾病占归因死亡约六成 | 有数据不给数据 |
```
